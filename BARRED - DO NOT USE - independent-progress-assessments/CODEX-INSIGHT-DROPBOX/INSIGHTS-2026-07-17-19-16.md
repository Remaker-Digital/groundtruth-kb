## Findings

### Finding A — `bridge/gtkb-wi5366-agent-red-frontend-gate-paths-003.md` is not a live defect [informational, closed]

`.claude/rules/file-bridge-protocol.md` already lists `NO-ACTION` as a
canonical status token. Both regexes `implementation_start_gate.py` actually
consults —
`scripts/implementation_authorization.py:71-73` and
`scripts/bridge_work_intent_registry.py:18-20` — already accept it, fixed by
commit `34b87b4e feat(gtkb): WI-4957 NO-ACTION first-class bridge status
across parser/routing/dispatch/auth/preflight - LO VERIFIED`, an ancestor of
current `HEAD`. `-003.md` is historical (the thread progressed through
`-004.md` GO and `-005.md` implementation report, now awaiting VERIFIED) and
must not be edited (append-only). Most likely historical explanation for the
owner's report: a *worktree* session pinned to a pre-`34b87b4e` commit, or
the packet-issuer singleton-contention race `-004.md` independently
diagnosed (`.gtkb-state/implementation-authorizations/current.json` is a
single global slot that a concurrent unrelated bridge's `begin` call can
occupy). No file change needed.

### Finding B — `_is_safe_command()` false-positive-blocks chained read-only commands [P2, live, reproduced] — `WI-5480`

`scripts/implementation_start_gate.py:872-894` requires exactly one
pipeline stage to grant the safe-command exemption, even though its own
`SAFE_COMMAND_PREFIXES` and `DIRECT_GIT_READ_ONLY_SUBCOMMANDS` allowlists
already cover the individual stages of many ordinary `&&`-chained
investigative commands. Live repro and full proposed fix design are in
`WI-5480`. Owner-approved scope; not yet implemented.

### Finding C — ~19 of ~36 duplicate status-token regex copies missing `NO-ACTION` [P2, backlog] — `WI-5475`

No single source of truth for the canonical bridge status-token set. Full
file inventory in `WI-5475`. Owner explicitly deferred this to backlog
(larger blast radius than the approved scope). This is the class of drift
most likely to reproduce the owner's *exact* original error text on some
other code path even after Findings B and D are fixed.

### Finding D — `implementation-start-gate.py`'s matcher excludes the `PowerShell` tool [P1, live, higher severity than B] — `WI-5481`

`.claude/settings.json` registers this hook with matcher
`Write|Edit|MultiEdit|Bash` — no `PowerShell`, unlike sibling hooks in the
same file. On this host, PowerShell is the primary shell tool. A protected-
path mutation via the PowerShell tool currently bypasses the mandatory
bridge-GO authorization check with no block and no audit-log entry. This is
a governance-coverage gap, not a reliability nit — plausibly more
consequential than Finding B. Confirmed no Codex-side parity gap (Codex has
no distinct PowerShell tool surface). Owner-approved scope; not yet
implemented. Sibling gap in `lo-file-safety-gate.py` tracked separately as
`WI-5477` (explicitly out of this scope).
