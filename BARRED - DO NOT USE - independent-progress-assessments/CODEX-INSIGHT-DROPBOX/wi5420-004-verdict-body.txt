## Blocking Finding — Claimed test evidence does not reproduce (2/12 fail)

**Claim.** Report -003: "Final focused suite: `12 passed, 1 warning in
6.23s`."

**Evidence.** Both failures raise the identical error, before either
test's own assertions run:
```
BridgeComplianceError: [Governance] Bridge artifact-head envelope
invalid: dispatchable bridge status NEW requires line 2 '::init gtkb lo'
and line 3 '::open build'. (Hard-block per
ADR-BRIDGE-ARTIFACT-HEAD-ENVELOPE-001 and
DCL-BRIDGE-ENVELOPE-LINE-AUTHORING-PLACEMENT-001.)
```

**Root cause.** The real production write paths
(`propose_bridge`/`propose_bridge_codex_non_bypass` in
`.claude/skills/bridge-propose/helpers/write_bridge.py`) both call
`normalize_bridge_envelope_head()` immediately before auditing. The two
new WI-5420 tests build content via a hand-rolled test helper that
injects author metadata but does NOT call
`normalize_bridge_envelope_head()`, then call
`_run_bridge_compliance_audit()` directly — bypassing the normalization
step the real writer always performs first. This gate was introduced in
a fully-committed commit (`35dfaf04`, "feat(envelope): verify slice b
bridge envelope head") that landed AFTER this report's evidence was
captured but is now live — the test fixture doesn't mirror the real
production call sequence, so the manufactured content is rejected by an
unrelated, already-live governance gate before either test reaches the
Cross-Harness Disposition logic it exists to exercise.

**Corroborating evidence.** Re-running the report's own "adjacent
diagnostic suite" command produces `15 failed, 36 passed` rather than the
claimed "38 passes and 13 pre-existing failures" — the arithmetic
reconciles exactly once the same 2 newly-broken tests are subtracted
(38-2=36 passed; 13+2=15 failed).

**Why this blocks VERIFIED.** `DCL-VERIFIED-SPEC-DERIVED-TESTING-MANDATORY-001`
requires linked specifications to have current, executed test coverage at
verification time. The report's own verification-plan table names these
exact two tests as proof for `DCL-CROSS-HARNESS-PARITY-ENFORCEMENT-001`
and `ADR-CODEX-HOOK-PARITY-FALLBACK-001`. Neither currently passes.
