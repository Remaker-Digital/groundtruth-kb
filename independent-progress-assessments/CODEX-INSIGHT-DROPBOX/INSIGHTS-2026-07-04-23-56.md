## Residual finding for the impl/verify stage (P3 hygiene)

**Claim.** The GO leaves the SoT registry edit-surface
`config/registry/sot-artifacts.toml` MECHANICALLY writable in the enforced
`target_paths`, guarded only by prose GO Condition 3 ("audit operates read-only
relative to source and configs it audits").

**Evidence.** `implementation_authorization.extract_target_paths` on `-001`
returns the inline JSON list verbatim (9 entries), including
`config/registry/sot-artifacts.toml` and
`groundtruth-kb/src/groundtruth_kb/project/sot_registry.py` as writable. The
impl-start gate scopes protected edits to exactly that list, so it will
authorize a registry write even though the PAUTH `allowed_mutation_classes` for
WI-5014 is "Read-only coverage audit artifacts and violation WI filing" and
`DELIB-202665455` forbids inline remediation. GO Condition 1 ("keep strictly
within the declared target_paths") reinforces the broad list; GO Condition 3
forbids the write in prose. That mechanical/prose split is the exact
two-sources-of-truth pattern this project exists to eliminate.

**Linked root cause.** The proposal's classification scheme includes a
`registry_gap` class (phase 4) but phase 6 only dispositions
`duplicate_sot_violation`. `registry_gap` handling is unspecified, which is the
latent reason the registry appears writable (implicit "register gaps inline").

**Impact.** Low-to-moderate. A headless implementation worker could write the
registry within the gate and rely on later verification to catch it, rather than
being blocked up front. In a SoT-singleton audit this is worth closing
mechanically.

**Recommended action (for Prime at implement time, and the WI-5014 verifier).**
Prefer one of: (a) file a REVISED `-003` narrowing `target_paths` to drop
`config/registry/sot-artifacts.toml` (registry is read via the
`groundtruth_kb.project.sot_registry` loader; read needs no target-path grant),
and state that `registry_gap` produces/links a remediation WI with no inline
registry mutation; or (b) treat GO Condition 3 as a HARD verify gate - the
WI-5014 impl report must show `config/registry/sot-artifacts.toml` was not
modified (e.g., clean `git status` for it) despite being in `target_paths`.
Also resolve `sot_registry.py`'s writable authorization (drop it or state a
read-only-helper intent).
