## Summary

Produce the authoritative inventory of every timer, TTL, timeout, backoff, interval, retry-count, and throttle value in GT-KB production surfaces, as the machine-readable artifact the downstream timer-governance slices consume. The inventory is generated by a deterministic, re-runnable extractor rather than a one-off regex, because a fresh re-derivation of the 2026-07-30 leader census performed while drafting this proposal did not reproduce that census (evidence below). This slice changes no timer value and adjusts no timer behavior.

## Claim

Prime Builder proposes the bounded inventory/census slice for `WI-5804` under the active whole-project authorization, keeping the bridge, project-authorization, owner-decision, and verification gates intact.

## Requirement Sufficiency

Existing requirements are sufficient. `DELIB-202667722` (timer governance is first-class; relaxed-first bias; registry visibility; no hard-coded timer values; recurring tuning) plus the `WI-5804` work-item description define the inventory scope and the per-value record shape. No new or revised requirement is needed before this implementation.

## Motivating Evidence - The Census Is Not Currently Reproducible

`WI-5804` records a leader census of "495 literal assignments in 138 production files; 815 including tests" from a regex over `scripts/`, `groundtruth-kb/src/`, and `.claude/hooks/`, describing the pattern as `NAME = <number>` assignments, with top carriers `check_modernization_git_lifecycle.py` 29, `release_candidate_gate.py` 25, `test_pipeline.py` 25, `deploy_pipeline.py` 21, `dispatcher_runtime.py` 17, `dispatcher_next/foundation.py` 16.

Re-derivation on 2026-07-30 at the current HEAD did not reproduce those figures under any regex tried:

| Extraction | Matches | Files |
| --- | --- | --- |
| Strict `NAME = <number>` (uppercase constant, production) | 346 | 163 |
| Strict `NAME = <number>` including `platform_tests/` + `groundtruth-kb/tests/` | 376 | - |
| Strict `NAME = <number>` filtered to timer keywords | 136 | - |
| Loose `*<timer-keyword>* = <number>` (any case, includes kwargs) | 203 | 75 |
| Loose, including tests | 399 | - |

Two specific contradictions, not rounding differences:

1. The named baseline top carriers contain essentially zero strict named-constant numeric assignments at HEAD: `check_modernization_git_lifecycle.py` = 0, `release_candidate_gate.py` = 0, `deploy_pipeline.py` = 2, `test_pipeline.py` = 1. The baseline therefore cannot have been produced by the `NAME = <number>` pattern its own description names. Under the loose keyword-filtered pattern those files do rank (`check_modernization_git_lifecycle.py` = 48), but then the totals and the other carrier counts diverge instead.
2. The classes the work item lists as *missed* by the census dominate the true population. Counted separately in production surfaces: `timeout=<literal>` 268, `sleep(<literal>)` 74, `busy_timeout` 25, TTL/expiry/backoff/retry kwarg literals 74, JSON config timer values 372, TOML config timer values 13. Named constants are a minority of the timer surface, not the bulk of it.

The divergence is reported as a finding, not resolved by fiat. Its consequence is a design requirement: the deliverable must be a recorded, re-runnable extraction specification whose output can be regenerated and diffed by any later session, so that no future slice inherits an unreproducible population estimate. The proposal deliberately does not adopt either number as canonical; the extractor's first run establishes the canonical baseline, and the divergence from the recorded prior census is captured in the artifact's provenance block.

## Proposed Scope

- Add `scripts/timer_inventory.py`: a read-only deterministic extractor that walks the declared production surfaces and emits the inventory artifact. It records its own extraction specification (patterns, surface roots, include/exclude rules) inside its output so the population is reproducible and diffable across sessions rather than re-derived by ad hoc regex.
- Cover all value classes, not only named constants: named numeric constants; inline call-argument literals (`timeout=`, `sleep(...)`, `busy_timeout`, TTL/expiry/backoff/retry kwargs); TOML and JSON configuration values; and hook-embedded values.
- Emit `config/governance/timer-inventory.toml` as the machine-readable artifact, with one record per value carrying: `file`, `line`, `name`, `current_value`, `unit`, `category` (claim/packet/lock/retry/poll/deploy/watchdog/session), `value_class` (named_constant/inline_literal/config_value), `invariant_coupled_to` (for example `DEFAULT_EXPIRY_MINUTES` bound to the work-intent claim max hold per `WI-4532`), `observed_failure_evidence`, and `relaxed_first_candidate`.
- Record observed-failure evidence against the values it belongs to, from the census already cited in `DELIB-202667722`: `WI-5694` (514/515 expired implementation-start packets), `WI-5788` (registry lock hard-timeouts), `WI-5784` and `WI-5795` (work-intent SQLite `database is locked` contention), and the protected-commit checker overrun.
- Record a `relaxed_first_candidate` per value as a *recommendation only*, expressing the relaxed-first bias from `DELIB-202667722`. Recording a candidate is not applying it.
- Include a provenance block in the artifact: generating commit, extraction-spec digest, per-class counts, and an explicit note of the divergence from the prior unreproducible census.
- Add `platform_tests/scripts/test_timer_inventory.py`: determinism (same input tree yields byte-identical output), value-class coverage against fixtures for each class, schema conformance, and an assertion that the extractor performs no write outside the single declared artifact path.

## Risk and Rollback

Principal risk is inventory incompleteness: an extraction spec that misses a value class silently understates the population and would propagate into `WI-5806` externalization. Mitigated by per-class fixture tests, by the embedded extraction spec making coverage auditable, and by the provenance block recording per-class counts so a later session can detect regression. Residual risk is accepted for this slice because the artifact is explicitly re-runnable and diffable.

Secondary risk is over-reach: an inventory slice drifting into value changes. Mitigated by the read-only extractor contract, the `git diff` acceptance criterion, and the explicit out-of-scope section.

Rollback: revert only the three declared target paths under separate authority. Because the slice changes no runtime timer value, rollback carries no timing-behavior consequence. Re-run the proposal's spec-derived tests and the bridge preflights to confirm restoration.
