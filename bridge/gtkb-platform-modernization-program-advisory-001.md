## Context-Loading Architecture

The target stack has three layers:

1. Harness-native startup capabilities provide only the compact invariant hints and locators that can be delivered with equivalent utility across supported harnesses.
2. The ::init session envelope mechanically resolves GT-KB role bootstrap and loads a generated session-baseline manifest.
3. The ::open activity envelope loads a generated specialized overlay for the active activity.

Runtime precedence is:

native hints -> GT-KB session envelope -> explicit role bootstrap -> activity overlay

An activity envelope cannot alter role. Missing or invalid role evidence fails closed.

Dispatched workers derive role from the explicit session envelope carried by the dispatched item. Dispatcher rules, harness-role routing maps, and harness identity are internal routing state and must not be loaded as worker role hints. The design must remain correct as dispatcher selection policy evolves.

The initial activity set is:

- ops
- deliberation
- build
- test
- spec
- project

Every session baseline and activity overlay classifies seven categories:

1. glossary
2. skills
3. CLI descriptions and access
4. source-of-truth descriptions and access
5. project and backlog status
6. operating context
7. work-subject knowledge

Manifests are generated from existing canonical registries. Imperfect generated output is evidence that a source registry should be improved; generated artifacts must not become hand-maintained competing authority.

## Freshness And Embedding Policy

- High-churn source-of-truth state is live-query-only and is not embedded.
- Low-churn authority such as accepted ADRs, DCLs, diagnoses, and stable system-design elements may be embedded when freshness and authority metadata are explicit.
- Embedded extracts carry source identity, authority class, generation time, TTL, churn class, and live-query route.
- A practical starting TTL should cover the usual interval between dispatch and the worker's first successful retrieval and extraction, commonly one to two minutes, while remaining evidence-calibrated by source class.
- Low-churn sources may justify longer TTLs.
- Expired, missing, conflicted, or unavailable information must be labeled and routed to recovery rather than presented as plausible current truth.
- Essential context is never silently discarded to meet a token target.

## Two-Tier Git Model

The approved model is:

1. Create one canonical project integration branch from develop.
2. Create ephemeral work-item branches from the project branch.
3. Workers make scoped automated commits only on the correctly bound work-item branch.
4. A work-item branch may merge into the project branch only after VERIFIED and required checks.
5. A completed project promotes to develop through a governed GitHub pull request.
6. Integrated develop promotes to stage only after integration and non-impairment gates.

Direct-push bypass fails closed. Automated commits include only claimed and authorized paths and preserve unrelated dirty work.

Dispatcher drain/quiescence is a restricted CLI lease, not an indefinite pause. It must be scoped, authorized, time-limited, auditable, crash-safe, automatically expiring, and incapable of silently suspending unrelated work forever.
