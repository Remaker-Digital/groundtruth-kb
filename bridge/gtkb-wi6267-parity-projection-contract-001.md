## Summary

`scripts/check_harness_parity.py` cannot validate full-body projections, so
the cutover Goose surface reports STALE 44 despite the projection engine's
0-drift `--check` and a current manifest. Measured mechanism (this session,
file:line):

1. A harness whose registry block declares `skill_adapter_manifest` is
   routed into the API-adapter branch (`expected_marker =
   "GTKB-API-SKILL-ADAPTER"`), demanding the retired compact-stub contract
   from a full-projection surface.
2. `ADAPTER_GENERATOR_BY_MARKER` (lines 160–164) has no
   `GTKB-GOOSE-SKILL-ADAPTER` entry, so even the correct marker resolves
   `expected_generator = None` and every adapter is STALE by construction.

The projections now carry the checker's own metadata contract (per
`1a89562cc`: marker block, `Generated by`, content-addressed
`Generated at`, `Canonical source`, `Canonical source sha256`), so only the
checker's routing and map need repair. This corrects the WI-6267 scope: the
original description blamed byte-comparison; the true mechanism is
marker-branch routing plus the missing generator-map entry (re-scoping per
`gtkb-baseline-correction-and-goose-projector-slice-1-006` F1).

## Scope

1. Route harnesses whose registry block declares `projection_engine` to
   their own harness marker (`GTKB-<HARNESS>-SKILL-ADAPTER`) regardless of
   `skill_adapter_manifest` declaration; the API-marker branch remains for
   the API-harness family.
2. Add `"GTKB-GOOSE-SKILL-ADAPTER": "scripts/harness_projection/project_harness.py"`
   to `ADAPTER_GENERATOR_BY_MARKER`.
3. Accept the content-addressed `Generated at` form (non-empty check is
   already sufficient; no change expected — asserted by test).
4. Regression tests (`test_check_harness_parity_projection.py`): a
   fixture projection carrying the engine's metadata block reports PASS;
   a fixture with a wrong digest reports STALE; a fixture lacking the
   block reports STALE; the API-harness branch still validates a compact
   stub. Live assertion: `--harness goose` reports zero STALE rows.
