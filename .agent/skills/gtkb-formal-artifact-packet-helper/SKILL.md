# /formal-artifact-packet-helper

Use this skill when a bridge proposal, implementation report, or approval gate
workflow requires generating or validating a formal-artifact approval packet.
This skill wraps the existing validated validation authority without
duplicating or replacing the canonical gate schema.

## Authority and Scope

- The **sole canonical schema authority** for formal-artifact approval packets
  is `.claude/hooks/formal-artifact-approval-gate.py` (the live gate). This
  skill is a helper wrapper, not a competing source of truth.
- The canonical CLI validator `scripts/validate_formal_artifact_packet.py`
  loads the live gate module at runtime and applies the same validation that the
  gate enforces at tool-call time. This skill recommends that validator for
  pre-insertion packet validation in bridge workflows.
- This skill does NOT open new approval paths, bypass the gate, mutate retired
  queue artifacts, or create packets outside the governed approval workflow.

## When To Use

- A bridge proposal or implementation report needs to demonstrate packet validity
  before filing.
- A Prime Builder or Loyal Opposition reviewer needs to validate an
  already-generated packet against the live gate schema.
- A work item requires packet generation guidance (stable LF normalization,
  required fields, artifact-type validation, approval-mode validation) and the
  developer wants the canonical recipe in one place.

## When Not To Use

- Do not use this skill to create a packet without following the governed
  formal-artifact approval workflow (bridge, owner AUQ, formal-artifact gate).
- Do not use this skill to replace, shadow, or override
  `.claude/hooks/formal-artifact-approval-gate.py` or
  `scripts/validate_formal_artifact_packet.py`.
- Do not use this skill to bypass root-boundary, credential-safety, or
  bridge-authority gates.

## Required Inputs

- Packet path (absolute or relative to project root).
- Approval context: proposal reference, bridge document name, approving
  deliberation or owner decision.
- Required packet fields from the live gate: `artifact_type`, `artifact_id`,
  `action`, `source_ref`, `full_content`, `full_content_sha256`,
  `approval_mode`, `presented_to_user`, `transcript_captured`,
  `explicit_change_request`, `changed_by`, and `change_reason`.
- Valid `artifact_type` values from the live gate: `architecture_decision`,
  `deliberation`, `design_constraint`, `governance`, `protected_behavior`, and
  `requirement`.
- Valid `approval_mode` values from the live gate: `acknowledge`, `approve`,
  `auto`, and `edit-and-approve`.

## Mandatory Steps

### Packet Generation

1. Identify the canonical required fields from the live gate
   (`.claude/hooks/formal-artifact-approval-gate.py` constants:
   `REQUIRED_PACKET_FIELDS`, `VALID_ARTIFACT_TYPES`, `VALID_APPROVAL_MODES`).
2. Construct the packet JSON with LF-only line endings (no CR, no CRLF).
   Normalize all string values to LF line endings before writing.
3. Write the packet to the appropriate approval directory (typically
   `.groundtruth/formal-artifact-approvals/`).
4. Validate the packet using the canonical CLI validator:
   `groundtruth-kb/.venv/Scripts/python.exe scripts/validate_formal_artifact_packet.py <packet_path>`
5. Record the validation output in the bridge artifact that cites the packet.

### Packet Validation

1. Run the canonical validator and capture exit code and output.
2. Exit 0: packet is valid. Cite the `packet_valid: <path>` output line.
3. Exit 1: packet is invalid. The gate's error message names the specific
   validation failure. Fix the packet and revalidate.
4. Exit 2: invocation error (missing gate, bad path, etc.). Resolve the
   environment issue before proceeding.

## Cross-Harness Notes

- This skill is a helper for bridge workflows consumed by Prime Builder and
  Loyal Opposition roles across all harnesses.
- The canonical packet validation authority (the live gate hook and the CLI
  validator) is Python-based and harness-agnostic. No per-harness adapter
  variation is needed.
- Codex, Antigravity, Cursor, and API harnesses all execute the same validator
  and gate; this skill's guidance applies uniformly.

## Verification Checklist

- `groundtruth-kb/.venv/Scripts/python.exe scripts/validate_formal_artifact_packet.py <packet_path>` exits 0.
- The packet file uses LF-only line endings.
- All `REQUIRED_PACKET_FIELDS` are present and non-empty.
- `artifact_type` is one of the `VALID_ARTIFACT_TYPES`.
- `approval_mode` is one of the `VALID_APPROVAL_MODES`.
- The packet is stored under `.groundtruth/formal-artifact-approvals/` with a
  stable, dated filename.
