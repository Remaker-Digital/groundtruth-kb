Owner design input (2026-07-03) — for-cause, time-bound dispatch quiesce

CONTEXT / FAILURE MODE (captured as WI-4997, P1):
During an owner-directed combined finalization of three entangled
dispatcher-modernization threads (WI-4992/4994/4995), an interactive LO set the
bridge substrate to `none` to quiesce automated dispatch and freeze the shared,
uncommitted source files. A Codex-A process reset the substrate back to
`dispatcher_daemon` ~13 minutes later, re-enabling dispatch; dispatched workers
then re-claimed and re-churned the threads (NO-GO looping), defeating the
interactive quiesce and blocking the owner-directed verdict finalization. There
is currently no reliable interactive/config-level mechanism to pause automated
dispatch that the autonomous system will not revert; the only effective stop was
a process-level governed control-surface halt performed by the owner.

OWNER DESIGN DIRECTION:
"Adding a for-cause time-bound quiesce command may be required in order to
provide a mechanism for clearing entangled commits. I don't know the best
solution, but this is a failure mode that needs to be addressed."

INTERPRETATION / DESIGN CONSIDERATIONS (LO framing, not owner-prescribed):
- for-cause: the quiesce carries an explicit, recorded reason (e.g., an
  entangled-commit clear, a governed maintenance window), so it is auditable and
  distinguishable from an accidental or malicious disable.
- time-bound: the quiesce auto-expires after a bounded window, so it cannot be
  forgotten and left disabling dispatch open-endedly (the open-ended substrate
  `none` was both forgettable and, worse, revert-prone). Auto-expiry also bounds
  the operational blast radius.
- authority / non-revert: while a for-cause quiesce is active, the autonomous
  dispatcher (daemon/supervisor and dispatched workers) must HONOR it and must
  NOT re-enable dispatch or re-claim threads until the window expires or the
  owner explicitly clears it. This is the load-bearing property the current
  substrate mechanism lacks — a dispatched worker was able to revert the
  operator's quiesce.
- purpose: the window exists specifically to let an operator/LO clear entangled
  commits (commit the shared files once, record verdicts) without racing the
  dispatch. It is the missing counterpart to the WI-4996 serialization defect
  (threads sharing target_paths implemented in parallel).

RELATIONSHIP TO EXISTING BACKLOG:
- WI-4997 (P1): the durable-quiesce control-integrity finding this input refines.
  The for-cause + time-bound + honored-until-expiry properties above are the
  owner-endorsed direction for that fix.
- WI-4996 (P2): the shared-target_paths serialization defect that produced the
  entanglement in the first place; a for-cause quiesce is the recovery mechanism,
  serialization is the prevention.
