## Blocking finding — WI-5185 test file is coupled to uncommitted WI-5189 source

- Claim: this report cannot be independently VERIFIED-finalized while WI-5189 is
  uncommitted; a per-report finalize would commit a broken-in-isolation state.
- Evidence:
  - The report edits `platform_tests/scripts/test_dispatcher_runtime.py` to add
    a `_write_prime_worker_session_document` helper (writing a
    `worker_role_provenance` session-envelope) and to rewrite
    `test_filter_prime_selected_stands_down_on_same_role_project_holder` and
    `test_run_dispatch_cycle_filters_held_prime_items_before_spawn` so they
    create those documents and set `GTKB_HARNESS_NAME`. The report itself
    describes these as the `document-authoritative Prime Builder claim fixtures
    required by the current WI-5189 contract`.
  - The dispatcher path under test consumes WI-5189 source.
    `scripts/dispatcher_runtime.py` imports `same_role_project_holder` from
    `bridge_work_intent_registry` and calls it while filtering held prime items.
    In `scripts/bridge_work_intent_registry.py`, `same_role_project_holder`
    matches holders by persisted `acting_role`, and `_resolve_acting_role`
    resolves that role through the newly-added `resolve_worker_role_provenance`
    document path — added by the still-uncommitted WI-5189 work (`git diff`
    shows the `resolve_worker_role_provenance` import and call as added lines).
  - The rewrite deliberately defeats the legacy path: it changes the holder
    session id from a dispatch-run-id-parseable form
    (`...T00-00-00Z-prime-builder-B-...`) to a non-parseable form
    (`...T000000Z-prime-builder-B-...`), forcing role resolution through the
    WI-5189 document path rather than the legacy dispatch-token/marker path.
  - Consequence: the two rewritten dispatcher tests resolve the holder's
    `acting_role` to `prime-builder` only because WI-5189 source is present in
    the working tree. A VERIFIED-finalize committing only WI-5185's two target
    paths (`scripts/dispatcher_runtime.py`,
    `platform_tests/scripts/test_dispatcher_runtime.py`) would commit a test
    file that fails against the committed (pre-WI-5189) registry source.
- Impact: VERIFIED is not cleanly achievable now; a per-report finalize would
  create a broken-in-isolation commit. This is the commingled-sibling
  finalization pattern (WI-5105 class): two GO'd work items sharing one working
  tree where one item's committed tests depend on the other's uncommitted
  source.
