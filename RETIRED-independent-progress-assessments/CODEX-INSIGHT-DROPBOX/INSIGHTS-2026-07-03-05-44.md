### Confirmed defect — Finding 1 (WI-4981): mid-session role switch silently no-ops

**Observation.** Owner selected "switch me to Prime Builder" and sent `::init gtkb pb`. The resolved role did not change: per-session marker `.claude/session/role-a9a96407-26f6-4358-8b31-ce759571c064.json` still read `"role":"loyal-opposition"` (written 04:10:57 by the session-start `::init gtkb lo`, never rewritten); `envelope.json` showed `role_resolved: loyal-opposition`, `interactive_role_source: null`. This turn's UserPromptSubmit hook fired **no** init-keyword-match message (session start's `::init gtkb lo` did).

**Empirical root cause.** Direct invocation of the UserPromptSubmit entry point:
```
python: from scripts import workstream_focus as wf
  wf._startup_role_mode_from_prompt('::init gtkb pb')  -> 'pb'          # matcher recognizes role
  wf._match_startup_init_keyword('::init gtkb pb')      -> gtkb/default   # keyword matches
  wf.handle_hook_payload({'prompt':'::init gtkb pb','session_id':'<fresh>'}, root) -> {'systemMessage': ...}
  role-<fresh>.json written?                            -> False         # role marker NOT persisted
```
`scripts/workstream_focus.py::handle_hook_payload` recognizes `::init gtkb (pb|lo)` (via `_CANONICAL_DISPATCH_INIT_RE`, line ~1064) and resolves `role_mode`, but does **not** invoke `_write_per_session_role_marker` (line ~1294) for a mid-session prompt. The marker-write is wired only to the SessionStart/first-message flow.

**Deficiency rationale.** An owner can select a role switch, receive no error, and continue believing the switch took — while the LO/PB mechanical gates (LO file-safety, implementation-start-gate, `changed_by` attribution) remain on the old role. Silent authority divergence between the transcript-declared role and the mechanically-enforced role is a governance hazard: had this agent simply *acted* as PB on the owner's say-so, every PB bridge/MemBase write would have been blocked or mis-attributed.

**Proposed fix (Prime Builder).**
- File: `scripts/workstream_focus.py`, function `handle_hook_payload` (mid-session canonical-init branch).
- Change: when `_startup_role_mode_from_prompt(prompt)` returns a role AND `_resolve_session_id` returns a non-null id, call `_write_per_session_role_marker(role_profile, session_id, ...)` (the same writer used by the first-message path), then surface a confirming `systemMessage`. Honor `DCL-SESSION-ROLE-RESOLUTION-001` assertion 6 (do not persist on `(None, None)` session id).
- Alternative (lower effort): if mid-session switching is intentionally unsupported, `handle_hook_payload` should return an explicit `systemMessage` stating the switch requires a fresh session — so it fails loud, not silent.
- Verification: parity test asserting `handle_hook_payload` with a mid-session `::init gtkb pb` payload writes a `role-<session>.json` carrying `prime-builder` (mirror `platform_tests/hooks/test_workstream_focus_session_role_marker.py`).

**PB implementation context.** Preconditions: this is a `.claude/hooks`-adjacent script change (tracked); goes through the normal bridge propose→GO→implement→VERIFIED cycle under an interactive-session-role-override spec set. Governing specs: `SPEC-CANONICAL-INIT-KEYWORD-SYNTAX-001`, `DCL-SESSION-ROLE-RESOLUTION-001`, `ADR-INTERACTIVE-SESSION-ROLE-OVERRIDE-001`.

### Confirmed risk — Finding 2 (WI-4982): divergent dual init-keyword grammars

**Observation.** Two matchers for one keyword family:
- `scripts/_session_init_keyword.py` `INIT_KEYWORD_REGEX`: **old** grammar — `(init|start|begin|open|initialize) (session|gtkb|gt-kb|groundtruth-kb|agent_red) [advisory]`; no `::` prefix, no `(pb|lo)` role, `agent_red` (not `application`).
- `scripts/workstream_focus.py` `_CANONICAL_DISPATCH_INIT_RE`: **canonical** — `^::init gtkb (pb|lo)$` per `SPEC-CANONICAL-INIT-KEYWORD-SYNTAX-001` v3.
- `_match_startup_init_keyword` tries the old matcher first, then falls back to canonical.

**Deficiency rationale.** Two grammars for one keyword invite exactly the inconsistency observed: the app-scope matcher and the role matcher disagree on syntax (`::`, role token, object vocabulary). Cross-harness init behavior becomes matcher-order-dependent.

**Proposed fix (Prime Builder).** Consolidate to a single canonical matcher honoring `SPEC-CANONICAL-INIT-KEYWORD-SYNTAX-001` v3; either remove the old grammar or map it as an explicit compatibility alias; lock with a grammar parity test.
