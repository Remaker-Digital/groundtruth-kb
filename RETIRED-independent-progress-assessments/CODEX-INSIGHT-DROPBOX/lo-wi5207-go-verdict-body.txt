## Premise Verification (independent, against live code)

The proposal's central claim — "completion reconciliation searches for a verdict
only on the primary bridge id" — is CONFIRMED by inspection of
`scripts/dispatcher_runtime.py` at the current HEAD:

- `_primary_bridge_id_for_launch` (lines 5257-5266) returns `primary_bridge_id`
  or the FIRST entry of `selected_documents` — a single representative, not the
  full selected set.
- In `_process_pending_exit_codes`, the LO-branch resolves that single
  `bridge_id` (line 5420) and polls for a verdict on it alone
  (`_find_dispatch_verdict`, lines 5422-5431).
- `dispatch_succeeded = (exit_code == 0 or post_verdict_exit_reconciled) and failure_reason is None`
  (line 5477) — one primary verdict (or a clean exit) marks the entire batch
  successful.
- On success the FULL batch `launch_signature` is retained
  (`recipient_state["last_dispatched_signature"] = launch_signature`;
  `last_suppressed_signature = None`) at lines 5480-5483, suppressing re-offer of
  every selected document, including any un-handled sibling.
- `_release_document_lease_records(last_launch.get("document_lease_handles"))`
  (lines 5472-5475) releases ALL per-document leases irrespective of which
  documents actually reached a role-correct verdict.

The `elif exit_code == 0` branch (lines 5459-5462) only guards the case where the
PRIMARY produced no verdict; it does not detect a sibling document left without a
role-correct verdict when the primary did produce one. This is precisely the
run-`211d49` scenario the proposal cites (primary WI-5203 `GO` + a declined
sibling `NO-ACTION`, exit 0). Premise accurate.

## Residual Risks / Verification Watch-Items (for post-implementation review)

1. Per-document signature/reoffer granularity. The proposal states it
   "preserves completed-document signatures, clears only incomplete-document
   signatures/reoffer state." The current model uses a single aggregate
   `launch_signature` plus a single `last_suppressed_signature` (lines
   5480-5483). The implementation must therefore recompute the retained
   signature over completed documents only (or otherwise leave the incomplete
   document's actionable signature un-suppressed) so the incomplete document
   genuinely re-offers. Verify at post-impl that an incomplete document is
   re-surfaced on the next tick and completed siblings are NOT re-offered.
2. Late-arriving-verdict race. The Risk/Rollback commits to launch
   timestamp/version boundaries and computing all selected outcomes before one
   atomic state write. Verification MUST include the mandated race and
   mixed-status fixtures (a verdict arriving just after process exit must not be
   mis-classed as incomplete; and vice-versa).
3. Classification distinctness. Confirm `selected_documents_incomplete` is a
   distinct reason in `bridge_dispatch_config.py` classification and is NOT
   surfaced as, or backed-off like, a generic `provider_failure`.
4. Sequencing. The proposal declares WI-5205 lands first because both touch
   `test_dispatcher_runtime.py` / `test_bridge_dispatch_config.py`. This GO does
   not authorize bypassing that ordering; Prime should sequence WI-5205 first to
   avoid shared-test-file churn. (WI-5205 is a distinct concern — NO-ACTION
   consumer semantics — not a duplicate of WI-5207's completion-evidence scope.)
