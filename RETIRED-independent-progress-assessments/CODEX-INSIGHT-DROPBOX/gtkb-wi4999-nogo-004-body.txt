## Findings

### [P1] BLOCKING: doctor.py cannot be VERIFIED-finalized in isolation (commingled with WI-4784)

- Claim: a WI-4999 VERIFIED verdict cannot be atomically finalized from the
  current worktree without violating the scoped-commit / cross-thread-capture
  invariant.
- Evidence: `groundtruth-kb/src/groundtruth_kb/project/doctor.py` is a required
  verified path (it holds the WI-4999 check function and is listed in the
  report's Files Changed). The same `doctor.py` also holds WI-4784's uncommitted
  role-authority-terminology hunks (cluster (b) above). The finalization helper
  `.claude/skills/verify/helpers/write_verdict.py --finalize-verified` stages
  whole files (`git add -f -- doctor.py`) and then commits the declared
  pathspec; git commits the entire staged `doctor.py` blob, so BOTH WI-4999 and
  WI-4784 hunks would enter the WI-4999 VERIFIED commit. The helper's
  `_assert_include_set_covers_report_claims` guard additionally requires
  `doctor.py` to be in the include set (the report carries no By-Reference
  Finalization Waiver), so `doctor.py` cannot be omitted from the transaction.
- Risk/impact: finalizing anyway would (1) fold a separate thread's
  un-VERIFIED changes into WI-4999's VERIFIED commit, breaking scoped-commit
  discipline and the bridge audit trail; and (2) commit WI-4784's changes
  outside its own finalization, corrupting that thread's provenance. Both are
  the governance violations the finalization gate exists to prevent.
- Recommended action: de-commingle `doctor.py` so each thread's hunks can be
  scope-committed independently (see Required Remediation).

### [confirmation] The WI-4999 implementation is otherwise verification-ready

- The spec-derived tests pass (4 of 4), both ruff gates are clean, the check

## Why NO-GO And Not VERIFIED

The Mandatory VERIFIED Commit-Finalization Gate in
`.claude/rules/file-bridge-protocol.md` makes VERIFIED valid only when the same
local transaction commits exactly the verified paths plus the verdict. Because
`doctor.py` cannot be committed in isolation from WI-4784's changes here, that
transaction cannot be constructed honestly, and a paper VERIFIED without the
commit is prohibited. NO-GO is the protocol-correct outcome: it preserves the
audit trail and returns a concrete, Prime-actionable (or owner-sequenced)
remediation.
