## Advisory observations (non-blocking)

### A2 [P3] — Hide-after-show is inherently reactive (implementation-report honesty)

- **Observation.** The mechanism binds `SetWinEventHook` to window-show events
  (`EVENT_OBJECT_SHOW`) and then calls `ShowWindowAsync(SW_HIDE)`. The hide
  necessarily happens *after* the console is shown.
- **Deficiency rationale.** `DELIB-20260707-NO-VISIBLE-CONSOLE-WINDOWS` requires
  that background automation "not surface visible consoles." A reactive
  hide-after-show still surfaces the console for a brief interval; the end-state
  is hidden, but a momentary flash is not fully eliminable for a window the
  platform does not spawn. This is a genuine limitation, not a defect — fully
  preventing the show would require intercepting Codex Desktop's own process
  creation, which is out of scope and materially more invasive.
- **Recommended handling.** The implementation report should frame the residual
  momentary flash honestly as a known limitation and state the end-state
  (hidden) as the achievable guarantee. Verification item 4 already asserts the
  end-state; it does not (and should not be read to) assert zero flash.

### A3 [P3] — VERIFIED requires live workstation evidence a headless verifier cannot produce

- **Observation.** Verification-plan item 4 requires a fresh 120-second Windows
  observation capturing at least one real Codex Desktop snapshot, recording that
  its console was hidden, the Git process exited naturally, and no `.git/index.lock`
  residue is attributable to the monitor.
- **Deficiency rationale.** That evidence is environment- and timing-dependent:
  it can only be produced on the workstation with Codex Desktop actively taking a
  snapshot during the observation window. A headless auto-dispatched LO verifier
  (this session's mode) cannot generate it, so a naive headless VERIFIED attempt
  would stall or under-evidence the live-nonimpairment requirement.
- **Recommended handling.** Plan the live-observation capture explicitly into the
  verification path — an interactive/owner-present capture or a recorded
  `.gtkb-state/ops/` evidence artifact carried into the post-implementation
  report — rather than discovering the dependency at VERIFIED time. The static
  tests (`test_codex_snapshot_window_hider.py`, `test_dispatcher_daemon_supervision.py`)
  and Ruff gates are headless-verifiable; the live nonimpairment observation is not.
