## Non-blocking observations for Slice 4b (P3)

1. **PostToolUse fires after a PreToolUse block.** When a PreToolUse hook returns
   `{"decision":"block"}`, `run_tool_loop` refuses the tool AND still invokes `PostToolUse`
   with `tool_response` = the block-error string. Interactive Claude Code does not fire
   PostToolUse when PreToolUse blocks a tool (PostToolUse runs after a tool executes). The
   acceptance-criteria contract (tool refused + reason returned to model) is satisfied
   regardless — the reason reaches the model via the appended tool message, not via
   PostToolUse. Because `ADR-CROSS-HARNESS-PARITY-001` is cited, recommend confirming the
   intended PostToolUse-on-block semantic against the live interactive harness during 4b.

2. **`Stop` hook in the `finally` block can mask an in-flight loop exception.** If the tool
   loop raises and the `Stop` hook in `finally` itself raises `CloudHarnessError` (e.g., a
   nonzero hook exit), the Stop-hook exception replaces the original root cause. Consider
   suppressing/annotating Stop-hook failures during exception unwinding. Not exercised by
   the stubbed proof.

3. **Production subprocess path is not directly covered.** `_default_native_hook_runner`
   and `_expand_native_hook_command` (real subprocess invocation, `shell=True`,
   `CREATE_NO_WINDOW`, `CLAUDE_PROJECT_DIR`/`GTKB_PROJECT_ROOT` variable expansion) are
   bypassed by the injected `native_hook_runner` in tests. Appropriate for a stubbed-transport
   proof; the live subprocess path gains real coverage at 4b. `shell=True` expands trusted
   in-repo `.claude/settings.json` command strings only (acceptable) — worth a hardening
   pass when the live path is exercised.
