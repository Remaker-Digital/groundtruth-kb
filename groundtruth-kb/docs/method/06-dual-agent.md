# 6. Independent building and review

Prime Builder and Loyal Opposition are immutable roles of distinct session
contexts. A harness, vendor or model does not hold a role. The exact supplied init
marker binds the receiving native context through the canonical CLI. A later
context on the same harness can be independent; the original author is never
required to return.

Prime Builder investigates, proposes, implements an independently accepted
proposal and reports the result. Loyal Opposition reviews and tests work it did
not author, emits its own verdict, and commits the complete independently verified
project when instructed by the native lifecycle. Review independence is not
waived because a change is small or documentation-only.

## One response at a time

An agent claims delivery of one exact next artifact. It does not own the work item,
chain or a later response. The bridge message is authoritative at receipt and has
no continuing authority. Each subsequent action re-queries canonical state.
A successor context obtains its own binding and claim; review never routes back
to a particular earlier agent.

| Received action | Responding role | Result |
| --- | --- | --- |
| NEW or REVISED proposal | Loyal Opposition | GO or NO-GO |
| GO proposal review | Prime Builder | Implementation and READY report |
| NO-GO proposal review | Prime Builder | REVISED proposal |
| READY implementation report | Loyal Opposition | VERIFIED or NOT-READY |
| NOT-READY implementation review | Prime Builder | Corrected READY report |

The complete native bridge contract also governs rejection, abandonment,
supersession and fresh verification. VERIFIED records exact-byte review and is
not proof that a Git commit exists. Terminal work is not reopened by a reply.

## Review the actual result

Load current specifications, work, parent project, test instructions, dependencies
and Git state through the CLI. A proposal describes its complete target paths and
specification-derived verification. Findings state the concrete claim, evidence,
impact, severity and needed correction. A report maps performed work to observed
tests and identifies gaps. Neither grep results nor a passing partial selection
proves all requirements. Writers validate complete agent-authored messages and do
not construct or repair the author's verdict.

Harnesses are independent clients. They communicate through CLI/domain services
and bridge/dispatcher, without reading a peer's configuration or coordinating
directly. The owner selects work until Dispatcher Next is independently qualified
and activated. Its design and diagnostics do not establish activation.

Keep routine engineering with the agent; ask the owner for material unresolved
product choices. Apply settled direction to canonical sources and preserve
unrelated work. See [sessions](07-sessions.md), [bridge coordination](12-file-bridge-automation.md)
and [the complete project lifecycle](14-lifecycle.md).
