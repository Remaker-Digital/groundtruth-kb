# A day of governed development

This illustrative workflow explains the current process; it is not an observed
host qualification, performance result or promise of unattended automation.

An owner selects a complete outcome and supplies an authoring context with the
literal init/activity and exact work. The actual host binds its native context
through the CLI, reads the current parent, formal requirements, executable tests
and dependencies, and loads root `AGENTS.md` plus the relevant shared skill and
baseline rule. [Harness projection](reference/harness-projection.md) explains the
single authored sources and each host's minimal registration/pointer route.

The context claims the next proposal artifact and authors the complete message.
The owner dispatches it to an independent review context. A rejected proposal
returns NO-GO for revision; an accepted proposal returns GO. The authoring
context implements the accepted scope and reports READY. Independent review
then returns NOT-READY or VERIFIED with exact byte and test evidence.

The project completes when all its members are independently VERIFIED and the
complete project commits through its native route and normal hooks. The message
cites every member work item. Bridge payloads and generated output do not enter
the work-product commit. Generated configuration is refreshed from its authored
baseline and projector.

If a context stops, its successor starts fresh, retrieves current canonical
facts and takes its own next-artifact claim. The predecessor's conversation,
scratch and host configuration are not continuity dependencies. An authorized
close/wrap harvest writes to existing canonical sources and uses native own-
scratch teardown; it does not invent an archive or trigger an automatic commit.

The owner chooses when work proceeds. Current owner dispatch is not replaced by
an old poller or inferred host role. Actual-host loading, trust, tool interception
and continuation require measured native evidence. The [independent context
setup](tutorials/dual-agent-setup.md) describes the practical sequence.
