# Clarify a plan or design

Use the scope supplied by the owner. If it is missing, ask for it before starting
the interview. Read current specifications, project/work-item state and relevant
implementation through the supported CLI and permitted checkout. Resolve factual
questions from those sources before asking the owner.

Identify the unresolved choices and their dependencies. Ask one material question
at a time, explaining the consequence of the available options. Use the receiving
harness's question interface when available. Do not require another harness or a
particular vendor tool. Reuse answers already supplied in this session; do not
repeat an approval request for work already authorized.

Apply a resolved choice directly to the affected canonical source or requested
action within the existing scope. For a new requirement needing intake, use the
current specification-intake interface. If the destination or material meaning is
unclear, resolve that uncertainty before mutation. Do not create a separate
decision archive, permission record or persistent interview state. The interactive
session log retains the conversation for later harvest when necessary.

At the end, give a concise account of what changed in canonical state and what
remains unresolved. Reference current source identifiers for applied changes.
An interview does not itself authorize implementation, create a bridge verdict or
invent a new project or work item.
