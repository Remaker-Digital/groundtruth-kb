# gtkb-advisory-disposition

Use `gtkb-advisory-intake` for the current intake procedure. Re-query current
canonical facts, compare the recommendation with existing work and explain the
useful next action within the owner's assignment.

Adopt, adapt, reject, defer and monitor are optional analysis words. They do not
constitute a closed disposition state machine or require a durable response
artifact. Ask an unresolved material owner question only when needed; apply the
result through the appropriate canonical writer and read it back.

Do not infer approval from an advisory, a prior conversation summary or a
classification word. Do not create a candidate ledger, permission record or
deliberation-based authority. Do not choose or dispatch implementation work.

Owner-selected implementation begins its own NEW chain after current project,
work-item, specification and test prerequisites. ADVISORY remains informational
and may have only another ADVISORY as its successor. A fresh context claims the
next artifact; it never owns the work item or inherits another context's claim.

Read current formal requirements and the baseline rule
`peer-solution-advisory-loop.md`. This skill does not resolve a session role or
activity; retain the explicit current binding and owner-selected scope.
