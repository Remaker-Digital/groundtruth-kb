# Checks for the selected harvest

Apply these checks to the activity or context being closed. A separately requested
audit follows its selected scope. No numbered-session cadence or historical
report collection is required for ordinary wrap.

- Re-query current work, parent project, formal requirements, tests and
  dependencies through the native CLI. Distinguish a recorded stage or dated test
  result from observed completion and the actual Git commit.
- Apply established owner decisions to the affected canonical source. Identify
  any material unresolved meaning or failed write; a handoff cannot carry the only
  copy of a fact needed for continuation.
- Check the exact bridge delivery and this context's next-artifact claim. Finish
  or release it through the supported command. A successor obtains its own claim;
  no claim or work-item ownership is carried by the summary.
- Preserve independent review, the complete project commit boundary and the
  difference between verified bytes and terminal committed work.
- Report the exact tests performed, failed cases, unexecuted obligations and
  coverage limits. Source scans and projection parity do not qualify actual-host
  behavior or a complete fresh/successor workflow.
- Preserve unrelated work and generated configuration. Inspect Git status in the
  registered checkout; do not use wrap as an instruction to stage, commit, push,
  clean, or force-add ignored material. Evidence retention follows its active
  qualification or incident purpose, not a permanent session archive.
- Tear down only this context's scratch directory through
  `gt session scratch-teardown` and read its result. Report `partial` as
  unfinished cleanup with the surviving entries; never as done. No hook runs
  the teardown at session end; the explicit verb does.
- Present optional next actions clearly as suggestions. Any continuation text
  is ephemeral; canonical domain state supplies recovery without it. Close and
  wrap leave the immutable binding intact and clear only transient activity.
