# Bridge delivery and work progression

GT-KB coordinates a specific artifact response through the native CLI. Use
`gt bridge show <document> --content --json` and `gt context task <work-item> --json`
to read the dispatched attempt and its current requirements. The owner selects
work until Dispatcher Next is independently qualified and activated.

A bridge message is authoritative at receipt and has no continuing authority.
Re-query canonical domain state before later actions. A successor context obtains
its own claim; the original author need not return. Independent review requires
a distinct eligible context.

Each receiving context claims only the next artifact it will deliver. A claim
confers no continuing ownership of a work item, project or other context's work.
Harnesses use their own configuration and communicate through CLI services and
bridge delivery. A harness never reads another harness's runtime state or asks
another harness to coordinate its work.

Use the current `gtkb-bridge` skill and the phase-specific proposal, review or
verification skill. Related review direction is in
`{{HARNESS_RULES_DIR}}/counterpart-review-gate.md`. Agent-authored proposals and
verdicts contain the complete routing header. The service validates and records
them without constructing or repairing the agent's message. Dispatcher selects
work and transports it; it does not author proposals or verdicts.

Implementation follows an independently accepted proposal. An implementation
report uses READY; review of that report produces VERIFIED or NOT-READY.
VERIFIED records independent review of exact Git mode and object identity.
When all project members are verified, the native CLI supplies the complete
project commit operation. Only the reviewed work product belongs in that commit.

Delivery is not dispatch, and neither delivery nor final prose proves that a
claim was completed. Read back the canonical result. A refused or unavailable
service is an incomplete operation with an actionable error, never success.

Bridge payloads are transient messages. Native attempt, claim, review and
terminal state controls recovery. Terminal cleanup removes disposable payloads;
Git records the committed work product. Follow the service's restart route when
an attempt cannot be continued from current canonical facts. An abandoned
attempt supplies no reusable GO, claim or effect authority.

Correct protocol defects through the affected source, tests and baseline.
Keep ordinary execution quiesced when live enforcement is known to contradict
the corrected protocol, until the corrected installation is qualified.
