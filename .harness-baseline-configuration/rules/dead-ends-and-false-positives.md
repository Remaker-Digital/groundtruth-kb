# Diagnose current failures

Reproduce a suspected defect against current canonical state and the installed
interface. State the expected behavior, actual result and smallest affected
scope. A past incident or conversational summary is a lead, not current evidence.

Read this context's own state and the native CLI result. Preserve unrelated work.
Do not search another harness's private files to explain this context's behavior.

Distinguish missing requirements, an implementation defect, stale installed
output and an invalid test fixture. Preserve a failed run as failed evidence;
a corrected rerun establishes a new result. Passing a selected check does not
establish full workflow readiness.

Apply a sufficiently defined correction to its source under the assigned scope.
Use the existing canonical work item or intake for remaining defects. A growing
session-history file is not a replacement for correcting mechanical behavior
and current agent direction.
