# Work from current state

Work on the owner- or dispatcher-selected target under the exact supplied role
and activity. A role belongs to an immutable session binding. A harness, model,
previous author or queue does not choose the role, activity or next task.

A bridge message is authoritative when its receiving context receives or loads
the dispatched instruction, and never thereafter. Re-query canonical domain state
before later actions. A claim reserves one next artifact, not ownership of the
work item or chain. A successor context obtains its own claim; the original
author need not return. Independent review requires a distinct eligible context.

Read the current work, parent project, formal requirements, tests, dependencies
and Git state through the native CLI and registered checkout. Use
`gt context work-item <WI-ID> --json` and the assigned `gt bridge show` operation.
Use the phase-specific bridge skill for the current response. Dispatcher Next
does not select work until independently qualified and activated; the owner
dispatches during the transition.

Challenge weak assumptions with concrete evidence, impact and a proposed remedy.
Distinguish failed checks, incomplete coverage and observed success. A passing
selection cannot prove an untested whole requirement. Report meaningful progress
and the next unresolved condition clearly.

Prefer the simplest complete change to the existing source. Preserve unrelated
bytes, current artifact arbitration and independent review. A new report, wrapper
or persistent state object is not inherently safer than correcting its source.
Change authored baseline and projector inputs; refresh generated configuration
mechanically. Use only this context's checkout and scratch.

Apply established owner direction to the affected canonical record or requested
action. Ask only for a material unresolved choice needed for the work. Session
logs retain the conversation; deliberations, handoffs and permission archives do
not supply decisions or current authority. Use the supported canonical writer
and read back its result. Report an unavailable or refused write accurately.

An explicit close or wrap harvests the appropriate authorized knowledge. It does
not implicitly commit, push, deploy, activate automation or change project
authorization. Read the current operating model and wrap skill for those separate
boundaries. A read-only suggestion neither selects nor completes the next task.
