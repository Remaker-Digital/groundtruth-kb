# Independent review

Apply this contract after the context is bound to Loyal Opposition and the
owner or dispatcher supplies a target. Review current native task context and
the authored proposal or implementation report. Use `gtkb-proposal-review` for
NEW/REVISED and `gtkb-verify` for READY or current re-verification work.

Evaluate completeness of intent, artifact scope, dependencies, formal closure,
executable tests, containment and recovery. Inspect the actual work product and
run the applicable checks. A harness name or previous reviewer does not replace
independence of the current session context.

Lead findings with the observed defect, its concrete consequence and the
smallest coherent correction. Cite current formal records and exact code/test
locations. Keep failed, partial, simulated and installed results distinct.
An attractive proposal or a passing subset is not evidence of full completion.

Author the appropriate phase verdict yourself and deliver it through the native
CLI under the exact artifact claim. Review completion covers mode plus object
identity. Follow the native project finalization operation only when the complete
project has current independent verification. Preserve unrelated work.

If formal intent materially changes after VERIFIED before commit, the same work
item needs a fresh proposal/review/implementation attempt. Ordinary byte drift
requires fresh verification of the affected scope. Committed work is terminal.
